## 保留与后续边界

- `SessionModel` 仍是单一会话协调者，负责开始、停止、重连和 UI 状态。未引入泛化插件层、依赖注入框架或新的第三方包。
- 旧钥匙串 ACL 兼容代码仍有 Apple deprecation 告警；本轮保留现有凭据读写行为，迁移需单独验证以免重复授权。SpeexDSP 上游 C 代码的既有告警也单独保留。
- 完整档案的回声匹配与写盘还会随记录增长；尚未做多小时性能验收。本轮改进的是实时显示取数，不代表整条音频/翻译链路已有固定低延迟保证。
- 音量门限不能辨认本人和同等响度的旁人。声纹识别、重叠人声分离和多型号耳机验证仍未完成。
- 当前是本机开发签名包，未做公开分发公证；不上传凭据、真实会议文字、截图、日志或签名产物。

## 0.7.0：本地与云端引擎（2026-11-02）

以 `TranslationEngine` 隔离传输/结果/结束，系统和麦克风共用音频处理与归档。Apple 实现复用已有本地管线，但完整模式不再只保留最新草稿：最终源句有界排队、自然结束并排空结果后保存。没有第三方依赖，也没有静默收费回退。

实机发现并修复 Apple 最终起点调整造成重复存档、持续修订引起中文闪回等待、纯标点噪声生成缺译记录，以及豆包空译文被标成定稿。旧档案兼容；来源标签仍表示通道。

84 项测试通过；本地与纯豆包各完成同一真实会议视频超过十分钟、同时开启麦克风，未发现累积队列或连接错误。本地 91 条系统 + 7 条麦克风全中英定稿；豆包 182 条系统全中英定稿，麦克风 5 条中一条服务未提供译文，原文与缺译提示保留。非空定稿事件与 JSON / Markdown 对账一致。68 组相同英文开头的增量返回比较本地较快，但数字、姓名和术语有明显差异，不能把速度当作准确率。

已验证系统采音的合成素材回归、模式点击/键盘、音源展开与收起及浅深色组件。真实会议样本仅一种；本人受控麦克风英语朗读、耳机热插拔与更长时间运行仍待专门验证。普通豆包模式保留 Apple 预览；对照专门关闭预览，结果不可误写为日常豆包首屏必然更慢。
